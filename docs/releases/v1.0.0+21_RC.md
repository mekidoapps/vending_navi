## Production OSM pilot, not a complete map

The approved run `osm-pilot-20260927-01` used manifest SHA-256
`8a79a98a270d81a476776cfaa7dc26a7d1ebc0951139862486b0062ce1122cb0`.
Production has 346 `osm_vending_seed` point documents and 406
`osm_vending_aggregate` documents, 752 public OSM documents total, plus a
server-only `osm_import_runs` run record with status `COMPLETED`. No native
or user documents were written by the pilot tool. `osm_vending_cells` is not
a Firestore collection.

The 406 aggregate documents derive from the **full canonical seed** while
the 346 points are a **pilot subset**. Aggregate counts do not imply that
their corresponding points are all present in Production. RC21 Alpha may
assess communication, Rules, App Check and map performance, **not nationwide
map completeness**. A coherent/full dataset and any 40,788-record Production
import require a separate decision and authorization.

The OSM Firestore Rules were deployed and matched Source Lock
`b44d6af78fd25beb7c6e8a0c09e359206ce1612d`; the two exact OSM indexes
are READY and the four prior indexes were preserved. Admin SDK read-only
query smoke returned Osaka aggregate/point 32/27 docs (75.6/83.3 ms),
Tokyo 22/9 (50.5/53.4 ms), normal urban 16/38 (38.7/48.6 ms), and suburban
12/1 (64.0/59.0 ms). These are **Admin SDK** latencies, not Pixel/App Check
end-to-end results. The Production app-client read path must be validated
on RC21 Alpha; desktop unauthenticated REST did not establish it.

# P6-05 30m重複候補判定

> 状態: 実装中
> 日付: 2026-08-11

## 決定

OI-005を次で固定する。

- 登録位置から30m以内を重複候補として扱う。
- メーカーに関係なく候補に含める。
- 実距離を計算し、近い順に並べる。
- 30m候補があるだけでは新規登録を禁止しない。
- 同一施設・隣接設置の複数台を登録可能とする。
- 二重送信防止は距離ではなく`requestId`冪等性で保証する。

## 読み取り

新しいFirestore直接read経路は作らない。

既存の:

```text
VendingMachineMapRepository.getMachinesInViewport()
```

を再利用し、

1. 30mを覆う小さい`MapViewportBounds`を生成
2. 既存geohash viewport queryで候補取得
3. Haversine実距離で30m以内へ絞り込み
4. 距離順に並べる

とする。

## UI

候補なし:

```text
候補画面を挟まず次へ
```

候補あり:

```text
近くに登録済みの自販機があります
→ 既存情報を見る
→ この自販機を更新
→ 別の自販機として登録を続ける
```

「この自販機を更新」の実処理はPhase 8で接続する。

## 実装境界

P6-05では重複検索Service / Controller / Screenを実装する。

ProductionのHome→位置→重複→登録方法までのルーティングはP6-06登録方法選択画面と同時に接続する。
これにより途中フェーズ専用の仮遷移を本番UIへ入れない。

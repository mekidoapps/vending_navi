# セキュリティ設計

## 1. 基本構成

```text
Flutter
├ 公開情報の読み取り: Firestore直接
├ 自分のプロフィール・よく飲む商品: 本人のみ直接読み書き
├ 自販機登録・更新・報告: Callable Functions
└ 写真: 本人専用一時Storage → Functionsで正式反映
```

公開自販機データをクライアントから直接書き換えさせない。

## 2. 公開・非公開範囲

| データ | 未ログイン読取 | ログイン読取 | クライアント書込 |
|---|---:|---:|---:|
| 有効な商品マスタ | 可 | 可 | 不可 |
| 有効なメーカーマスタ | 可 | 可 | 不可 |
| 公開中の自販機 | 可 | 可 | 不可 |
| 有効な商品情報 | 可 | 可 | 不可 |
| 公開中の写真情報 | 可 | 可 | 不可 |
| 検索インデックス | 可 | 可 | 不可 |
| 更新履歴 | 不可 | 不可 | 不可 |
| 報告・修正提案 | 不可 | 不可 | 不可 |
| 他人のユーザー情報 | 不可 | 不可 | 不可 |
| 自分のユーザー情報 | 不可 | 可 | 許可フィールドのみ |
| 自分のよく飲む商品 | 不可 | 可 | 可 |

## 3. Firestore Rules方針

### 公開マスタ

- `isActive == true`のみ読み取り可能。
- 書き込みはAdmin SDKのみ。

### 自販機

- `status == active`等、一般公開対象のみ読み取り可能。
- クライアント書き込み禁止。
- `hidden`、`removed`、`merged`等の詳細は運営のみ。

### 商品・写真

- 親自販機が公開可能で、子ドキュメントも`isActive/status`が公開状態の場合のみ読み取り可能。
- クライアント書き込み禁止。

### ユーザー

- `request.auth.uid == uid`を必須とする。
- `accountStatus`、作成日時等を本人が変更できないよう、許可フィールドを限定する。
- 他人のドキュメントは読み取れない。

### 履歴・報告・制限

一般クライアントのread/writeをすべて拒否する。

## 4. Storage Rules方針

### 一時領域

```text
machine_uploads/{uid}/{uploadId}/original.jpg
```

- ログイン必須
- パスUIDと認証UID一致
- 他人の一時画像は読取不可
- 許可MIMEタイプのみ
- ファイルサイズ上限
- 1アップロードのファイル数制限
- 正式反映後または期限切れで削除

### 正式領域

```text
vending_machines/{machineId}/{photoId}/original.jpg
vending_machines/{machineId}/{photoId}/thumbnail.jpg
```

クライアントから直接アップロード・削除させず、Functions/Admin SDKで管理する。公開画像の配信方式とStorage読取ルールは、URL方式を含め実装前に確認する。

## 5. Functions共通チェック

1. Authentication
2. App Check
3. `accountStatus`
4. 入力スキーマ
5. 文字数、件数、ファイル上限
6. Product ID / Manufacturer ID / Machine ID実在性
7. 位置範囲
8. 許可状態値
9. `requestId`冪等性
10. 投稿回数制限

### ユーザー状態

- `active`: 通常利用
- `restricted`: 投稿・更新不可。閲覧は可能
- `suspended`: 投稿・更新・報告・フィードバック等を拒否

停止範囲の最終詳細は実装時にテストケースへ固定する。

## 6. App Check導入順

1. 開発環境でdebug provider
2. Android本番プロバイダを設定
3. メトリクス確認
4. Functionsで強制
5. Storageで強制
6. Firestoreで強制

App Checkは認証・Rules・入力検証の代替としない。

## 7. 投稿回数制限

管理対象:

- 新規自販機登録
- 商品更新
- AI認識
- 写真追加
- 修正提案
- 報告
- フィードバック

具体的上限はクローズドテストの正常利用回数とAI費用を見て決める。フィードバックのみ既存案として30秒間隔・1日20件を基準候補とする。

## 8. 冪等性

- 操作ごとにUUIDの`requestId`を生成する。
- `uid + requestId + operation`を重複判定キーとする。
- 同じリクエストを再送した場合、最初の結果を返すか`already-processed`を返す。
- 対象: 登録、商品更新、写真追加、修正提案、報告。

## 9. UGCモデレーション

### 共有データ

公開後の自販機情報は作成者の私有データではなく、共同で維持する共有データとする。

### 現地で直接更新可能な低影響項目

距離条件等の具体値は保留だが、ログインユーザーが現地にいることを確認できる場合、次を直接更新候補とする。

- 商品追加・無効化
- 推定から確認済み
- 売り切れ設定・解除
- 写真追加
- 場所メモ

### 提案・報告とする高影響項目

- 位置
- メーカー
- 撤去
- 重複
- 立ち入り不可
- 写真の非表示・削除
- 自販機全体の削除・統合

### 公開状態

```text
active
underReview
hidden
removed
merged
```

### 報告状態

```text
new
reviewing
resolved
rejected
```

報告1件だけで自動非表示にしない。MVPはFirebase Consoleで運営確認する。

## 10. ログとプライバシー

### 記録候補

- Function名
- 操作種別
- 成功・失敗
- エラーコード
- requestId
- 処理時間
- アプリバージョン
- 認証UID（運営ログの必要範囲）

### ログへ出さない

- メールアドレス
- 写真の一時URL
- AIへ送った画像内容
- 詳細な緯度経度
- フィードバック本文
- AI生レスポンス全体

## 11. 必須セキュリティテスト

- 未ログインの公開読み取り
- 未ログインの直接書き込み拒否
- ログイン済みでも自販機直接書き込み拒否
- 他人のユーザーデータ拒否
- 履歴・報告・制限情報の読取拒否
- 不正ID・状態値・座標の拒否
- App Checkなしの拒否（強制後）
- `restricted` / `suspended`の拒否
- 同一requestIdの二重処理防止
- 他人の一時写真へのアクセス拒否
- 非画像・サイズ超過ファイルの拒否
